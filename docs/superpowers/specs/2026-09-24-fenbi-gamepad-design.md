# 手柄刷题脚本设计

- 日期：2026-09-24
- 状态：待评审
- 目标文件：`fenbi-gamepad.user.js`（新建，第 5 个脚本）
- 相关文件：`fenbi-memorize-layout.user.js`、`fenbi-ai-sidebar.user.js`

---

## 一、目标与边界

### 1.1 要解决的

躺床上用手柄刷粉笔背题页，不碰键鼠完成整个循环：**看题 → 选答案 → 看解析 → 翻下一题**，外加回退网页、交卷、开关 AI 助手面板。

成功的样子：

| | |
|---|---|
| 插上就能用 | 手柄连上、按一下任意键被识别，页面角标亮起显示手柄名 |
| 每个动作能自己绑 | 手柄型号不定，绑定界面里按一下手柄上的键就绑上 |
| 不干扰原来的 | 鼠标键盘照常用；手柄不抢焦点、不发合成键盘事件 |
| 不装另外两个脚本也能跑 | 选选项 / 翻题 / 滚动 / 交卷 / 回退走的都是粉笔原生 DOM |

### 1.2 明确不做

| 不做 | 为什么 |
|---|---|
| 填空题软键盘 | 用户明确排除。手柄打字要么做摇杆选字母的软键盘，要么上外接键盘，都是另一个项目 |
| 通用空间导航（任意网页） | 用户选定只做粉笔刷题场景。通用导航是另一套架构（焦点模型 + 元素可达性计算），不在这个脚本里 |
| 合成键盘事件 | 见 4.4。跟现有快捷键撞车，且谁先跑取决于监听顺序，出了 bug 极难查 |
| 震动反馈 | `vibrationActuator` 是 Chrome 专属，也不是需求。YAGNI |
| 每个动作的「装了 / 没装另外两个脚本」双路径 | 用户会三份全装（README 里「询问 AI」那条链路本来就要求装齐）。第二条路径是白写的。YAGNI |

> 「双路径」指的是**每条动作都写两套实现**。「当前第几题」的读取回退（2.2）不在此列 —— 那是一处约 20 行的查询，不是动作的执行路径。

## 二、架构

### 2.1 四层，以及那条分界线

一个文件里四层。**关键约束：①② 层不碰 DOM，③ 层不碰手柄。**

```
① 输入层   rAF 循环 → 读 buttons[].pressed / axes[]
           只在有手柄时跑；页面 hidden 时停
    ↓ 交出「这一帧按下了什么」——一个纯粹的按键标识集合
② 识别层   与上一帧 diff → 边沿事件
           按钮：按下沿触发一次
           按住：首次延迟 400ms，之后每 80ms 重复
           摇杆：死区 0.35，越过死区当方向键，共用同一套重复规则
    ↓ 交出「动作 id」
③ 动作层   ACTIONS 表：id → { 名字, 默认键, 执行() }
           执行时要么操作粉笔 DOM，要么 dispatch 事件给别人
④ 配置层   GM_getValue / GM_setValue 存「动作 id → 按键标识」
           按键标识 = {type:'button', index:0}
                     | {type:'axis', index:1, dir:-1}
```

**为什么这么切**：② 层全是纯函数（死区判定、边沿判定、重复计时、按键标识的序列化与比较）。这层最容易写错 —— 死区算错就是「摇杆一碰就飘」，重复计时算错就是「翻页翻飞」—— 而它不碰 DOM，所以能在 Node 里直接测，不用起 jsdom、不用等真定时器。③ 层不碰手柄，意味着测试里可以绕过整个输入链路直接调动作。

### 2.2 与另外两个脚本的契约

沿用仓库既有约定：**普通 `Event` + DOM 属性，不用 `CustomEvent.detail`**（README 第 422 行：跨沙箱传 detail 不稳，属性是两边都看得见的普通 DOM）。命名照 `fbai-ask` / `data-fbai-ask` 那套来。

#### 契约一：开关 AI 助手面板

现有 `fbai-ask` 是「递题目过去」，没有开关。新增一条：

| 名字 | 值 | 谁写 | 谁读 |
|---|---|---|---|
| `TOGGLE_EVENT` | `'fbai-toggle'` | 手柄脚本 dispatch | 侧边栏监听 |
| 结果属性 | `data-fbai-toggle-result` | 侧边栏写 | 手柄脚本读 |

握手照 `askAi()` 的样子：**擦掉旧结果 → dispatch → 读结果属性 → 清理**。结果码 `shown` / `hidden` / `none`（侧边栏没装）。读不到 `none` 之外的码就不做事，也不报错。

改的是 `fenbi-ai-sidebar.user.js`，加一个监听 + 一个 `ui.toggle()` 调用 —— 它已经有 `ui.toggle()` 了（快捷键 `Ctrl+Alt+Q` 走的就是它）。

#### 契约二：当前在第几题

背题页是**一整条长列表**，不是一题一屏。布局脚本里的 `getCurrentQuestionIndex()` 已经在算这个：先按 DOM 标记找，找不到就取**离视口 35% 高度最近的那道题**，结果带 TTL 缓存。

布局脚本把结果写到 `documentElement` 上：

| 名字 | 值 | 谁写 | 谁读 |
|---|---|---|---|
| 当前题号属性 | `data-fbai-current-question` | 布局脚本 | 手柄脚本 |

手柄脚本读这个属性；**读不到就自己按同一套 35% 视口启发式算一遍**（约 20 行）。这样装不装布局脚本都能用。

> ⚠️ **必须配一条契约测试**。照 `test/` 里那条 `assert.equal(layout.ASK_EVENT, sidebar.CONFIG.askEvent)` 的样子：两侧的名字对不上，表现是「按了没反应，页面上一点线索都没有」—— 正是最该被测死的一类。

### 2.3 界面

**设置浮层** —— GM 菜单一项「手柄设置…」开一个 shadow DOM 浮层，跟侧边栏同风格。内容：

- 顶部：检测到的手柄名 + `mapping` 是不是 `standard`
- 一张动作表：动作名 / 当前绑的键 / 「重新绑定」按钮
- 「重新绑定」→ 提示「按下手柄上的键」→ 抓下一个手柄输入 → 存 → 立刻生效，不用刷新页面
- 全部恢复默认

**角标** —— 页面角落一个小标 `🎮 Xbox Wireless Controller`，没手柄时不显示。

角标不只是好看：**浏览器安全策略要求先按一下手柄上的键，`getGamepads()` 才会返回它**。插上不动等于没插。没这个提示，用户会以为脚本坏了。

### 2.4 文件与测试

| 文件 | 内容 |
|---|---|
| `fenbi-gamepad.user.js` | 单文件，形态与另外三个一致：IIFE + `module.exports` 出口，Node 里导出纯函数供测试，浏览器里 `init()` |
| `test/gamepad.test.mjs` | ② 层纯函数（死区、边沿、重复计时、按键标识序列化）+ ④ 层配置读写 |
| `test/gamepad-action.test.mjs` | 假手柄灌进 `navigator.getGamepads`，验「按下 → 第 3 题的 label 真的被 click 了」 |

## 三、交互设计

### 3.1 默认映射

8 个动作要塞进有限几个键，这是唯一的真矛盾。默认这么排 —— **全部可改**，这只是起点。

**关于按键称呼**：文档里一律用**标准映射的索引**（0–16）和方向（十字键 / 左摇杆 / LB / RB / LT / Start / Back），不用 A/B/X/Y。因为索引 0 是「下面那个键」，在 Xbox 上是 A、PS 上是 ×、Switch 上是 B —— 顺着手柄叫名字，换个手柄就全反了。这正是要自己映射的原因。

| 手柄 | 动作 | 说明 |
|---|---|---|
| 面键（索引 0 / 1 / 2 / 3） | **选项 1 / 2 / 3 / 4** | 直选。索引 0 是「下面那个键」，落在不同手柄上名字不同 |
| 十字键 → / ← | 下一题 / 上一题 | 长按连发 |
| 十字键 ↑ / ↓ | 上滚 / 下滚 | 长按连发，一步约视口 1/3 |
| 左摇杆 | 连续滚动 | 模拟量，推得越远滚越快 |
| LB | 展开 / 收起解析 | |
| RB | 呼出答题卡跳题浮层 | 十字键选题号，面键 0 跳过去 |
| LT | 提交（多选题用） | 单选题用不上 |
| Start | 开关 AI 助手面板 | |
| **Back 短按** | 回退网页 | `history.back()` |
| **Back 长按 1 秒** | 呼出设置 / 按键帮助浮层 | 躺着忘了哪个键干什么，按它 |
| **Start 长按 1 秒** | 交卷 | 见 3.3 |

### 3.2 为什么「选项用四个面键直选」

备选是「摇杆移动高亮 + A 确认」：只占两个键、键位宽裕，但多一步操作，而且**必须在页面上画一个高亮框**，否则不知道选到哪了 —— 等于要多做一套视觉层。

躺着刷的场景下，直选明显更对：一看就知道按哪个，且不引入新 UI。代价是四个面键全占掉，别的动作往肩键 / 十字键 / Start / Back 上挤 —— 这正是 3.1 那张表的由来。

### 3.3 防误触是总原则

躺着的时候手柄容易压到，而**交卷不可逆** —— 误触一次整套练习就交了。所以：

- **所有动作走边沿触发**（按下那一刻响应一次），只有滚动和翻题这两个明确要连发的走长按重复
- **交卷 = 长按 1 秒 + 二次确认**，故意做得难按
- **`document.hidden` 时整个轮询停掉**，切到别的标签页就不响应

### 3.4 一个还没验证的点

**多选题的「提交 / 确认」按钮在粉笔 DOM 里长什么样，我没查过。** 3.1 里 LT 那条是占位。

实现时第一件事就是把它找出来。找不到的话（比如粉笔的多选是选完自动提交），LT 就得改绑别的动作。

## 四、错误处理与边界

1. **没手柄** → 轮询不启动，角标不显示，脚本静默。零开销。
2. **手柄断开**（`gamepaddisconnected`）→ 停轮询、撤角标、**清掉「按住中」的状态**。不清的话会卡在连发里一直翻页。
3. **粉笔改版、目标元素找不到** → 执行前探测，找不到就静默跳过 + `console.warn`，不弹窗不崩。跟仓库现有风格一致 —— README 里脱库那段就是「拦下来说一声，不装作成功」。
4. **不做合成键盘事件** → 一律直接操作 DOM。这是一条**约束**，不是实现细节：一旦开始发合成 keydown，就会跟 AI 面板的 `Ctrl+Alt+Q` 那类现有快捷键撞车，而且谁先跑取决于监听顺序，出了 bug 极难查。
5. **`mapping !== 'standard'` 的杂牌手柄** → 按键索引没有标准含义（标准映射下索引 0 是「下面那个键」：Xbox 是 A、PS 是 ×、Switch 是 B）。所以绑定界面必须**同时显示索引和原始值**让人按着试，并在浮层里明说「你这个手柄不是标准映射，默认键位可能是错的」。
6. **输入框聚焦时跳过选选项** → 页面上的自定义刷题数量输入框拿到焦点时，手柄按面键不该去选 A。因为不发键盘事件，打字本身没问题；但「选选项」这个动作要主动跳过。
7. **性能** → rAF 循环里只做数组读取和纯计算，**不查 DOM**。DOM 查询只在动作真正触发那一刻做。这是不掉帧的关键。

## 五、测试策略

### 5.1 那个坑

**jsdom 完全没有 Gamepad API** —— `navigator.getGamepads` 不存在，`gamepadconnected` 事件不存在。另外 `requestAnimationFrame` 要开 `pretendToBeVisual` 才有，而现有夹具没开。

所以测试脚手架要：

- 给 `navigator.getGamepads` 打桩，返回可控的假 `Gamepad` 对象（`{id, mapping, buttons:[{pressed,value}], axes:[]}`）
- 让 rAF 能被**手动步进**，而不是等真定时器 —— 等真定时器测试会飘

这两样收进 `test/harness.mjs` 里新增的 `bootGamepad()`，**不污染现有夹具**。现有 15 个测试文件都得继续能跑。

### 5.2 测什么

| 层 | 怎么测 |
|---|---|
| ② 识别层 | 纯函数直接喂帧序列。重点：死区边界（0.349 不触发 / 0.351 触发）、按下沿只触发一次、长按的 400ms/80ms 节奏、松开后状态清干净 |
| ④ 配置层 | 假 GM 存储读写往返；没存过时落回默认；坏数据（存了条不存在的动作 id）不炸 |
| ③ 动作层 | 起 jsdom，灌假手柄，步进 rAF，断言「按下面键 1 → 第 3 题的 `label.choice-radio-label` 收到 click」 |
| 契约 | `gamepad.TOGGLE_EVENT === sidebar.CONFIG.toggleEvent`；`gamepad.CURRENT_QUESTION_ATTR === layout.CURRENT_QUESTION_ATTR` |

### 5.3 回归底线

现有 15 个测试文件全部保持通过。改动只碰 `fenbi-ai-sidebar.user.js` 的加信道那部分，所以重点盯 `test/panel.test.mjs` 和那条已有的信道契约测试。

## 六、实施前要做的验证

按顺序，前两件没结论之前不该动手写动作层：

1. **多选题的提交按钮长什么样** —— 见 3.4
2. **背题页的选项能不能被脚本 click** —— 存档 HTML 里 `input` 带 `disabled`（那是答完之后的快照）。要在真实未作答的页面上确认点 `label.choice-radio-label` 有效
3. **`getCurrentQuestionIndex()` 的 35% 启发式在实际滚动中稳不稳** —— 不稳的话手柄会选错题，这是最严重的失效模式
4. **`fbai-toggle` 加进侧边栏后，原有快捷键不受影响**

## 七、实施顺序

1. ④ 配置层 + ② 识别层（纯函数，TDD，全程不碰 DOM）
2. ③ 动作层，先做「选选项 + 翻题」两条，在真实页面上验手感
3. 加角标 + 设置浮层（绑定界面）
4. 加契约：`fbai-toggle` 信道、`data-fbai-current-question` 属性
5. 补齐剩余动作：滚动、解析、跳题、交卷、回退
