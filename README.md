# 粉笔背题页增强

一套给粉笔（fenbi.com）背题页面用的工具，四部分：

| | 是什么 | 跑在哪 |
|---|---|---|
| [**fenbi-memorize-layout.user.js**](#一布局与解析面板) | 布局重排、自建解析面板、复制题目、「询问 AI」按钮 | 粉笔页面 |
| [**fenbi-ai-sidebar.user.js**](#二ai-侧边栏) | 页面左侧悬浮的 AI 面板，支持 13 家 | 粉笔页面 |
| [**ai-autofill.user.js**](#三豆包端自动填写) | 收到题目填进输入框并发送 | AI 站点页面 |
| [**fenbi-ai-unframe/**](#四去头扩展) | Chrome 扩展，让 AI 站点能被嵌进页面 | 浏览器 |

三个脚本可以分开装，各干各的。但「询问 AI」这条链路要**三份都装齐**才通 —— 见[下面那一节](#五询问-ai这条链路为什么绕这么大一圈)。

## 一、布局与解析面板

核心解决一件事：**点完选项等解析的那一下卡顿**。

| | 原版 | 装了之后 |
|---|---|---|
| 点选项出解析 | 等 Angular 取数 + 渲染，肉眼可见地卡一下 | 从已缓存的数据瞬时渲染 |
| 考点 / 来源 | 只有被渲染过的题才有，且只显示第一个考点 | 全部题目都有，多考点完整显示 |
| VIP 视频 / 笔记 | 占据大片版面 | 隐藏 |
| 题目宽度 | 跟随窗口无限拉宽 | 限宽 900px 居中，右侧给答题卡留位 |
| 题目 / 选项 | 白色圆角块，无边框，靠 20px 底色间距分隔 | 各自成卡片：边框 + 圆角 + 淡阴影，选项之间留 10px 间距 |
| 解析 | 展开时和 Angular 的折叠动画打架，会闪 | 自建面板，默认折叠，头部带「复制题目」「询问 AI」「解析和展开」 |
| 答题卡 | 原生 | 右上角自制悬浮答题卡（原生答题卡移出屏幕，跳转逻辑保留）；**没有题目时整张卡不显示** |
| 自定义刷题 | 出题数量只有 5/10/…/40 八档 | 那一行的第一格（`5`）变成输入框，1–500 任意填（**界面已就绪，尚未接到粉笔接口**，见下） |

### 拦截接口，一次拿全

背题页的解析数据来自 `tiku.fenbi.com/combine/static/solution`。这个接口**一次性返回整份练习所有题目的** `solution` / `source` / `keypoints` / `correctAnswer`。

脚本在 `document-start` 同时挂钩 `XMLHttpRequest` 和 `fetch`，把这份响应抄下来存进 `Map`。`globalId` 和页面上 `app-ti[data-question-key]` 一一对应，所以能精确地把数据挂到对应题目上。

> 为什么不自己发请求？因为 URL 里的 `key` 参数不在页面 HTML 里，由粉笔的前端运行时生成，脚本无法复现。挂钩是唯一可靠的办法。

### 自建解析面板

粉笔对每道题的解析区是**懒渲染**的：你没点过的题，`app-result-common`、`app-solution-overall` 这些节点根本不在 DOM 里，连正确答案的高亮都没有。点完选项之后 Angular 才去渲染，这就是卡顿的来源。

脚本改为在每题的 `.ti-container` 里挂一个自己的 `.fb-sol-panel`，内容全部来自缓存。面板默认隐藏，在 `document` 上用捕获阶段的 `click` 监听选项，点到就立刻加 `.fb-sol-visible` —— **抢在 Angular 前面**，不等网络也不等渲染。

同时把原生 `app-result-common` 整块隐藏（里面只有 video / solution / keypoint / source / note，全是这个脚本本来就要隐藏的），页面上只留一套解析 UI，不会再出现“闪一下再折叠”。

### 修掉一个自我触发的重排死循环

这是卡顿的真正技术原因，也是 2.0 最大的改动，值得单独说：

原版脚本里 `updateCustomCard()` 每一轮都会无条件写 `count.textContent = ...`。而写 `textContent` 会移除旧文本节点、插入新节点，**产生新的 mutation**；MutationObserver 又正好监听 `document.body` 的 subtree，于是再次触发自己。结果是：

```
写入 → mutation → observer(150ms) → 全页重扫 + 80 次 innerText 强制重排 → 写入 → ...
```

一个永动的 150ms 循环，每轮都在一个 700KB 的 DOM 上强制同步布局。

2.0 做了三件事断掉它：

- **所有写操作先比对再写**：`setText()`、`important()`（比对 `getPropertyValue` + priority）、`classList.toggle(name, force)`。值没变就不碰 DOM，不产生 mutation，循环自然收敛。
- **热路径里删掉全部 `innerText`**：`innerText` 会强制同步重排，改用 `textContent`。
- **冷热分离**：`optimizeDynamic()`（面板同步 + 答题卡）跟着 mutation 走；`optimizeQuestionWidth` / `optimizeOverall` / `hideVipModules` 降级为 1.5 秒一次的低频兜底——这些选择器 CSS 本来就全覆盖了。

另外 `getCurrentQuestionIndex()` 的几何回退要读 40 次 `getBoundingClientRect`，加了 250ms 缓存，不再每次 mutation 重算。

### 配置

脚本顶部 `CONFIG`：

| 键 | 默认 | 说明 |
|---|---|---|
| `questionMaxWidth` | `900` | 题目最大宽度（px） |
| `cardWidth` | `240` | 答题卡宽度（px）。和 `.fbac-body` 的内边距是一对，见下 |
| `cardTop` / `cardRight` | `65` / `16` | 答题卡位置（px） |
| `cardBottom` | `16` | 答题卡下边缘离屏幕底留多少（px）。和 `cardTop` 一起决定卡片的 `max-height` |
| `cardGap` | `14` | 答题卡和答题区之间的空隙（px） |
| `minCellWidth` | `33` | 题号格子的最小宽度（px）。一行几个由它和卡宽算出来 |
| `gridGap` | `7` | 题号格子之间的间距（px） |
| `zIndex` | `900` | 层级。必须和侧边栏的相等，且落在粉笔内容层（500）和暂停遮罩（1000）之间 |
| `observerDelay` | `150` | MutationObserver 防抖（ms） |
| `layoutInterval` | `1500` | 低频布局兜底周期（ms） |
| `currentIndexTTL` | `250` | 当前题号几何回退缓存（ms） |

答题卡占掉的横向空间是**算出来的**，不是另一个要手动同步的旋钮：

```js
const RIGHT_RESERVE = CONFIG.cardRight + CONFIG.cardWidth + CONFIG.cardGap;
```

改 `cardWidth` 就够了。写死的话，改了卡宽忘了改预留，答题卡会直接压在题目上，而且一点报错都没有。

### 一行几个题号：从实测宽度算

以前是 `CONFIG.columns = 5` 写死的。卡放宽了还是 5 列 —— 每个格子白白变胖；卡被媒体查询压窄了还是 5 列 —— 格子就挤了。2.6 起改成从题目区的实测宽度算：

```js
const columns = Math.floor((width + gap) / (minCellWidth + gap));
```

宽度靠 `ResizeObserver` 拿，**不在 mutation 的热路径里** —— 这份脚本被「自我触发的 150ms 重排循环」咬过一次，热路径里每轮读几何尺寸正是当初的病根。

量的是 `getBoundingClientRect().width`（边框盒），**不是 `clientWidth`**。题号多了会出滚动条，`clientWidth` 要减掉滚动条宽度，于是「出现滚动条 → 少一列 → 内容变矮 → 滚动条消失 → 多一列 → …」来回抖。边框盒不含滚动条，反馈回路从根上不存在。

（也没用 `scrollbar-gutter: stable` —— 那会永久窄掉一块内容，默认的 5 列就会变成 4 列。）

### 内边距和卡宽是一对，不能拆开改

题号区实宽 = `cardWidth` − 2（面板边框）− `.fbac-body` 内边距 × 2，而这个实宽决定一行几个题号。默认那组数是：

```
240 − 2 − 16 × 2 = 206  →  floor((206 + 7) / (33 + 7)) = 5 列
```

所以**想再加留白就得把卡宽一起加上去**。单独把内边距从 16px 调大（或者把 `cardWidth` 调回 220），实宽就掉到 206 以下，默认列数从 5 变 4 —— 页面上不会报错，只是题号格突然变少一排的样子。

`test/card.test.mjs` 里有一条断言把这个算式钉住了：它同时校验 `cardWidth` 的推导值和 CSS 里 `.fbac-body` 的 `padding`，改其中任何一个都会红。

### 题目多了自己滚

卡片有 `max-height: calc(100vh - cardTop - cardBottom)`，超出部分**由题号那一格自己滚**，标题行、状态行、底部「当前：N」都不动。

不给滚动的话题目一多卡片就一路长到屏幕外面，那三行正是滚动时最该一直看得见的。实现上是卡壳 → `.fbac-panel` → `.fbac-body` → `.fbac-grid` 一条竖向 flex 链子，中间两层都写了 `min-height: 0` —— flex 子项的默认最小高度是内容高度，少写一处底下那个 `overflow-y` 就永远不触发，而且页面上看着完全正常，只是滚不动。

### 没题目就不显示

答题卡原来是不问青红皂白就挂在页面上的 —— 目录页、解析页、首页这些地方没有题目，卡片上只剩「0/0」「共 0 题」，白占一块地方还压着底下的内容。

现在**没有题号就把整张卡收起来**。判据用的正是这张卡要显示的东西：粉笔原生答题卡里 `.answer-btn` 有几个。一个都没有就是没数据 —— 要么题还没加载出来（那就等它加载好再露），要么这一页压根不是答题页。

这也是它唯一会出现的方式：卡片建出来时就是藏着的，之后每轮 `updateCustomCard` 按题号数量决定露不露。粉笔是单页应用，从答题页点回目录页走的正是同一条路，卡片跟着收起来，不用另接路由。

实现上踩到两个坑，都记在这儿：

**一、隐藏规则必须写成 `display: none !important`。** 卡片自己那条 `#fenbi-custom-answer-card` 把 `display` 钉成了 `flex !important`，而 CSS 是**先比重要性、再比特异性** —— 一条不带 `!important` 的类选择器根本盖不住它。表现是「隐藏类加上了，卡片照样杵在那儿」，而且一点报错都没有。`test/card.test.mjs` 里有一条专门盯着这个感叹号。

**二、从藏变露那一次得重量一遍宽度。** 藏着的时候 `display: none` 没有盒子，`getBoundingClientRect()` 量出来是 0 宽，`computeColumns` 会把 0 兜成 1 列。不重量的话卡片会先以 1 列的样子画出来，等 `ResizeObserver` 下一轮回调才跳回 5 列 —— 一眼能看见的闪。所以 `applyCardVisibility()` 的返回值特意区分了**「这一下刚露出来」**和**「一直露着」**：只有前者才需要重量，后者每轮都量等于把热路径又拖回读几何尺寸的老路上。

### 层级：两个助手得压在同一档上

现象是点「暂停答题」之后，粉笔那层半透明遮罩**盖得住 AI 面板、盖不住答题卡** —— 满屏灰里独独浮着一张答题卡。

这个坑分两层，第一层修错了，值得完整写下来。

**第一层（错的判断）**：看着像两个助手的 `z-index` 差了一位，于是把两边调成同一个数。**没用。**

**第二层（真身）**：粉笔的遮罩是 `DIV.modal-overlay`，`position: fixed`、`z-index: 1000`、盖满屏幕、`rgba(0,0,0,0.5)`。而侧边栏的**宿主元素**压根没有 `z-index`（是 `auto`）—— 宿主是 `position: fixed`，本身就是一个层叠上下文，所以 shadow 里 `.wrap` 那个再大的数也只能在宿主内部排序，对外整个面板仍然停在 `auto` 那一档。

于是浏览器看到的实际是：

| | 实际排在哪一档 | 遇到遮罩（1000） |
|---|---|---|
| 侧边栏 | `auto`（宿主没设 z-index） | 在下面 → **盖得住** ✓ |
| 答题卡 | `2147483646` | 在上面 → **盖不住** ✗ |

一个在 `auto` 档、一个在正数档,**这两个数根本没法比** —— 所以「把两边调成同一个数」这条路走到黑也修不好。面板被遮住跟它那个数字毫无关系。

**修法**是两件事一起做：给宿主补上 `z-index`，再把两边都压到遮罩之下、仍在粉笔页面元素之上。取值区间是：

```
500  —— 粉笔页面元素里最高的那个（--z-index-footer）
900  —— 两个助手
1000 —— 粉笔「暂停答题」的遮罩
```

比 500 低会被页脚那类东西压住，比 1000 高就浮到遮罩上面去了。

**测试守的也从数字改成了关系。** 原来那条钉的是 `zIndex === 2147483000` —— 数对了、关系是错的，答题卡照样浮在遮罩上，测试却一直绿着。现在断言两条：宿主必须自己带 `z-index`（`test/panel.test.mjs` 里真的 `boot()` 起来读宿主元素），以及两个助手的值必须落在 500 和 1000 之间。

### 「下载」按钮：先拦下来

答题界面上那个下载按钮现在**点了没任何反应**，只往控制台打一行日志。

拦截挂在 `document` 的**捕获阶段**，并且 `preventDefault` + `stopPropagation` + `stopImmediatePropagation` 三件套齐全。少任何一件，粉笔自己的 Angular 监听照样会跑，文件照样下下来，而从页面上完全看不出脚本没生效 —— 这是这类「先拦着、以后再加功能」的写法最容易骗过自己的地方。

留着口子：

```js
window.fbDownloadHook = element => { /* element 是那个 <app-download> */ };
```

塞了函数就调它，钩子里抛错不会连累页面。

### 自定义刷题：任意出题数量（界面已就绪，尚未接线）

在 `www.fenbi.com/spa/tiku/guide/catalog` 的「自定义刷题」弹窗里，出题数量那一行的**第一格**（原来那个 `5`）变成一个输入框，可以填 1–500 之间的任意整数。10 / 15 / 20 / 25 / 30 / 35 / 40 都不动。

**代价是 `5` 这个预设没了**，要 5 道得自己敲。之所以顶掉第一格而不是在末尾加一格：八个小方块那一行本来就是满的，第 9 格会把行撑爆，和旁边几个方块摆在一起一眼就是硬塞进去的。

那个 `5` 是**藏起来**，不是从 DOM 里删掉 —— 它是 Angular `*ngFor` 渲染的，身上挂着粉笔自己的点击监听，从人家的清单里挖掉一个节点，下一轮重建时对不上。留着它、只是 `display: none`，粉笔那边完全不知道自己少了一格。

**这个数字目前还没有真的传给粉笔。** 这一版只做了两件事：把 UI 放上去，以及打一个探针，看点了「保存」之后粉笔到底发了什么请求。

原因是那样做不猜：数量的候选值由 `*ngFor` 渲染，Angular 的监听挂在原生的那几个按钮上，脚本克隆一个出来的话样式对、点击没反应；唯一的正路是顺着 `__ngContext__` 摸到组件实例，而组件实例长什么样只有运行时才知道。

探针做的事：点了「保存」之后，把 3 秒内所有 `XMLHttpRequest` / `fetch` 的**方法、URL、请求体**逐条打出来（逐条即时打印，不是攒到最后汇总 —— 保存多半会跳页，跳了控制台就清了），外加本地存储的增量和那个按钮上的 Angular 上下文。

```js
fbCountProbe.summary()   // 看汇总
fbCountProbe.last()      // 看最后一条请求
```

下一版按探针的结果接线。

## 三、豆包端自动填写

跑在豆包页面里。粉笔那边的脚本够不到跨域 iframe 里的输入框 —— 那是一堵墙。唯一能碰豆包输入框的，是跑在豆包页面自己里面的脚本，也就是这一个。

收到题目后：找输入框 → 填进去 → **自动发送**。

### 找输入框：按几何特征，不按 class

豆包的 class 是一长串 Tailwind 工具类加一个带哈希的后缀（比如 `enhanceBtn-W9xBoi`），改版就换一批，认不住。所以按形状认：**面积最大的那个可编辑区域**，面积相同取更靠下的。同时排除上半屏（那是对话记录）、隐藏的（富文本编辑器常留一个隐藏 textarea 兜底）、太小的。

### 发送：按位置认按钮，加上硬性半径

同理不认 class。发送按钮唯一稳的特征是**在输入区的右下角** —— 这个位置关系由「人手够不够得着」决定，不是哪个前端随手写的。

三层筛：

1. 在输入框横向中点**右边**（左边那排「深度思考」「联网」点了会改设置）
2. 在输入框顶边**以下**（上方是对话记录和它的操作按钮）
3. 距输入框右下角 **160px 以内**

取最近的。那个半径是有意加的硬上限：**选不中顶多发不出去，选错了就是在你的页面上乱点按钮**。超过半径就不点，退回模拟回车。

填完等 250ms 再发 —— 富文本编辑器把内容同步进自己的状态要一个 tick，早了发送按钮还是灰的，点了没反应而且是静默的。

发完 900ms **回头验一眼编辑器空了没有**。点下去和真发出去是两件事，不验的话「点了但没生效」会一路装成成功。没清空就弹提示，并在控制台打一张周边按钮的表。

### 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `autoSend` | `true` | 填完自动发。改成 `false` 就只填不发 |
| `sendDelay` | `250` | 填完等多久再发（ms） |
| `sendVerifyDelay` | `900` | 发完等多久回头验（ms） |
| `allowedOrigins` | 粉笔三个域 | 只认这些来源发来的消息，**没有通配符** |
| `searchFrom` | `0.4` | 只在下 60% 找输入框 |
| `waitTimeout` | `12000` | 等输入框出现的上限（ms） |
| `hideTexts` | `['下载电脑版']` | 顺手藏掉的按钮，按文字认 |

### 页面上的测试入口

脚本跑在页面上下文（`@grant none`），所以控制台直接敲得到：

```js
fbaiTest()              // 单独测「找输入框 + 填入 + 发送」
fbaiFill('题目原文')     // 拿真题试，跳过拼接
fbaiDump()              // 打印输入框周边所有按钮，按离右下角的距离排序
```

`fbaiDump()` 是发不出去时用的：`距右下角` 那一列最小的、又不带「禁用」的，就是真的发送按钮。

还有 `Ctrl+Alt+F`（Mac 上是 `Ctrl+Option+F`）快捷键，但控制台那条更稳 —— 三键组合有可能被浏览器或输入法先吃掉，吃掉了还不报错。

## 四、去头扩展

ChatGPT、豆包这些站点都发了 `X-Frame-Options` / `Content-Security-Policy`，禁止自己被别人 iframe 嵌进去。所以要嵌进粉笔页面，得先把这两个响应头去掉。

装在 Chrome 里的 MV3 扩展，用 `declarativeNetRequest` 改响应头。**作用范围是收窄的**：

```json
"resourceTypes": ["sub_frame"],
"initiatorDomains": ["fenbi.com", "localhost"]
```

只有**由 fenbi.com 页面发起的子框架请求**才会被改。不影响你正常访问这些站点，也不影响别的网站嵌它们。

> ⚠️ 这个扩展的用途就是关掉目标站点的防嵌入保护。它的权限清单里列了 13 家 AI 站点的域名。**只在你自己的浏览器上、为了这个用途装**，测完不用了就禁用掉。

## 五、「询问 AI」这条链路，为什么绕这么大一圈

点击解析面板上的「询问 AI」，题目会出现在豆包的输入框里并被自动发送。中间隔了三堵墙：

```
粉笔页面                                    豆包页面（iframe / 独立窗口）
┌─────────────────────────────┐
│ 布局脚本                     │
│   ├─ 把题目写进 DOM 属性      │
│   └─ 派发 fbai-ask 事件       │
│          ↓                   │
│ 侧边栏                       │
│   └─ postMessage ────────────┼──────→  ai-autofill
│                                          ├─ 找输入框
│      ← data-fbai-ask-result ─┼──────────┘ ├─ 填入
│         （结果码）             │            └─ 发送
└─────────────────────────────┘
```

**两个脚本各在自己的油猴沙箱里，看不到对方的变量，也调不了对方的函数。** 能共用的只有 DOM。所以：

- 题目写在 `documentElement` 的 `data-fbai-ask` 属性上，配一个 `fbai-ask` 事件通知
- 侧边栏处理完，把结果码写回 `data-fbai-ask-result`，布局脚本读出来决定按钮上闪什么字
- 用**属性 + 普通 Event**，不用 `CustomEvent.detail` —— 跨沙箱传 detail 不稳，属性是两边都看得见的普通 DOM

这套东西有个特点：**改了一边忘了另一边，表现是「点了没反应」，没有任何报错，页面上也没有线索。** 所以有一整组测试专门盯着「两边名字一致」：

```js
assert.equal(layout.ASK_EVENT, sidebar.CONFIG.askEvent);
assert.equal(layout.ASK_ATTR, sidebar.CONFIG.askAttr);
assert.equal(sidebar.CONFIG.askTag, autofill.CONFIG.messageTag);
```

跨域那一步用 `postMessage`，**目标 origin 写死成 `https://www.doubao.com`，不是 `*`** —— 用 `*` 的话任何嵌进来的页面都能收到这条消息。

送不出去的时候（选的是 ChatGPT 这类没有配套脚本的站点），题目退回剪贴板而不是静默丢掉 —— 静默丢掉是最差的，用户会以为脚本坏了，而其实题目就在手边。

面板收起来的时候题目来了会自动弹回来，不然填进去了也看不见。

```bash
npm install
npm test
```

219 个用例，跑在 Node 内置的 test runner + jsdom 上。

**测的是要发布的代码本身，不是它的副本。** 三个脚本都是单文件、无构建，出口长这样：

```js
if (typeof module !== 'undefined' && module.exports) {

}
```

所以改完 `.user.js` 直接 `npm test` 就行，没有构建步骤。

```
ai-autofill.user.js            纯函数、几何启发式、编解码、来源校验
fenbi-ai-sidebar.user.js       面板行为、菜单、投递目标决策
fenbi-memorize-layout.user.js  复制题目、布局常量、答题卡列数、下载拦截、自定义数量
fenbi-ai-unframe/              扩展
test/
  harness.mjs                  在 jsdom 里把侧边栏真跑起来的共用夹具
  make-fixture.mjs             从题库存档生成测试夹具
  panel.test.mjs               面板行为，以及「和答题卡统一」的跨脚本比对
  card.test.mjs                答题卡的列数算法与滚动
  download.test.mjs            下载拦截：判定 + 真起一个 DOM 验事件传播顺序
  count.test.mjs               自定义出题数量的解析与注入
  *.test.mjs                    219 个用例
```

`card.test.mjs` 和 `count.test.mjs` 里都要从源码里抠 CSS 声明块或纯函数来断言。抠 CSS 的时候**不能用 `/\{([\s\S]*?)\}/`** —— 模板字符串里的 `${CONFIG.xxx}` 自带一个花括号，非贪婪匹配会正好断在那儿，于是「块里没有 `overflow-y`」这种**假失败**就出现了。`card.test.mjs` 的 `cssBlock()` 两头都认缩进，就是为这个。

jsdom 不做排版，`getBoundingClientRect` 恒等于 0，所以「按形状 / 位置挑元素」那几段逻辑，测试里得自己把矩形塞进去（`test/autofill.test.mjs` 里的 `candidate()` 和 `place()` 就是干这个的）。测量和挑选因此是分开的两个函数 —— 挑的那半是纯的，好测。

**测试夹具不含题库内容。** `test/make-fixture.mjs` 在你本地从 `*背题.html` 存档生成 `test/fixtures/`，两者都在 `.gitignore` 里，不随仓库分发。

## 常见问题

**Q：解析没出来 / 面板是空的？**
先看控制台有没有 `接口解析缓存` 那条日志。没有的话说明接口拦截没命中——可能是粉笔改了接口路径，改 `API_KEYWORD` 常量即可。

**Q：刷新之后解析全都不见了？**
2.1 已修。2.0 的面板只认“本次加载里点过选项”，刷新把状态清零就会满页空白。现在已答的题会自动显示解析入口。

**Q：解析入口什么时候显示？**
三种情况任一即可：点过该题选项、该题已作答、该题是填空题。除此之外保持折叠，正文要手动展开。

**Q：接口挂了脚本会整个失效吗？**
不会。保留了 DOM 兜底：缓存没命中时退回抓原生 `section-solution` / `section-source` / `section-keypoint`。只是这种情况下又会回到“粉笔渲染过才有”的老行为。

**Q：点了「询问 AI」没反应？**
按这个顺序看：

1. 控制台有没有 `[粉笔 AI 侧边栏] 收到询问请求` —— 没有就是侧边栏没装或装的是旧版（看启动日志里的版本号）
2. 下一行 `投递结果：sent / copied / none` —— `copied` 说明退回剪贴板了，多半是当前选的不是豆包，或 iframe 还没建好
3. 切到豆包那一帧的控制台（DevTools 的 Console 左上角 `top` 下拉）看有没有 `[AI 自动填写] 收到题目`。**iframe 里的日志不会显示在顶层控制台**，这一步最容易漏

**Q：填进去了但没发出去？**
控制台会打一张周边按钮的表。在豆包页面敲 `fbaiDump()` 也能随时看。贴到 issue 里，`距右下角` 那一列最小的就是真的发送按钮。

**Q：公式题显示不正常？**
解析正文是把接口返回的 HTML 直接 `innerHTML` 注入的（和粉笔自己渲染的是同一份）。粉笔的原生 `app-format-html` 组件可能对公式（MathLive）做了额外处理，注入的原始 HTML 有可能渲染不到位。遇到的话开 issue 附上题目。

**Q：正确选项的高亮还是慢？**
选项高亮由粉笔原生逻辑负责，脚本没有接管。接口返回里有 `correctAnswer.choice`，理论上可以自己上色，但改动选项组件风险较高，所以没做。

## 已知限制

- 只在**背题页**（`/ti/memorize/...`）实测过。做题页、模考页的 DOM 结构不同，不保证生效。
- **自定义刷题的那个输入框目前只是个界面**，填了数字不影响出题数量 —— 请求长什么样还不知道，等探针的结果。见[上面那一节](#自定义刷题任意出题数量界面已就绪尚未接线)。
- 依赖粉笔的接口路径和 `data-question-key` 属性；`ai-autofill` 依赖豆包的 DOM 形状。任一方改版都可能失效，上面几条自检日志和 `fbaiDump()` 就是用来快速定位的。
- 题目内容全部来自粉笔自己的接口，脚本不生成也不存储任何题目内容。
- 自动发送打开后，**白名单内的页面可以替你按下发送**。挡住这件事的只有 `allowedOrigins`，所以那份清单里不能出现通配符，也不要往里加你不信任的域名。

一个实现上的注意点：

- 选项卡片**没有**写死 `background`。卡片本身就是白底，透明即白底；一旦写死就会盖掉粉笔原生的 `:hover` 变色。

### 2.1

修两个“解析不显示”的问题。两者现象像、根因不同：

- **多选点了没反应** —— 点选项的监听只认单选的 `.choice-radio` 那一套 class，多选用的 `.choice-checkbox` / `.option-checkbox` 不在里面，点了不会展开面板。现已补齐。
- **刷新后所有题的解析都不见了** —— 面板可见性原先**只**由“本次页面加载里点过这个选项”决定，而原生解析块又被 CSS 无条件隐藏。刷新会把“点过”的状态清零，于是满页空白。现在改为**已答即显示**：加载时判断题目是否已作答（单选/判断/多选看选项上的 `correct` / `wrong` / `correctLost`，填空等用“粉笔是否已渲染原生解析”兜底），已答的直接露出解析入口，不用再点一遍。
- **填空题解析常显** —— 填空题没有任何选项元素可点，改为无条件显示。
