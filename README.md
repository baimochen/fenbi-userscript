# 粉笔背题页增强

一套给粉笔（fenbi.com）背题页面用的工具，五部分：

| | 是什么 | 跑在哪 |
|---|---|---|
| [**fenbi-memorize-layout.user.js**](#一布局与解析面板) | 布局重排、自建解析面板、复制题目、「询问 AI」按钮 | 粉笔页面 |
| [**fenbi-ai-sidebar.user.js**](#二ai-侧边栏) | 页面左侧悬浮的 AI 面板，支持 13 家 | 粉笔页面 |
| [**ai-autofill.user.js**](#三豆包端自动填写) | 收到题目填进输入框并发送 | AI 站点页面 |
| [**fenbi-ai-unframe/**](#四去头扩展) | Chrome 扩展，让 AI 站点能被嵌进页面 | 浏览器 |
| [**fenbi-gamepad.user.js**](#五手柄操作) | 用手柄刷题：选选项、翻题、滚动、跳题、交卷 | 粉笔页面 |

四份脚本可以分开装，各干各的。但「询问 AI」这条链路要**三份都装齐**才通 —— 见[下面那一节](#六询问-ai这条链路为什么绕这么大一圈)。

## 一、布局与解析面板

核心解决一件事：**点完选项等解析的那一下卡顿**。

| | 原版 | 装了之后 |
|---|---|---|
| 点选项出解析 | 等 Angular 取数 + 渲染，肉眼可见地卡一下 | 从已缓存的数据瞬时渲染 |
| 考点 / 来源 | 只有被渲染过的题才有，且只显示第一个考点 | 全部题目都有，多考点完整显示 |
| VIP 视频 / 笔记 | 占据大片版面 | 隐藏 |
| 题目宽度 | 跟随窗口无限拉宽 | 按比例让出 AI 面板和答题卡两栏，剩下的全归它，随屏幕缩放 |
| 题目 / 选项 | 白色圆角块，无边框，靠 20px 底色间距分隔 | 各自成卡片：边框 + 圆角 + 淡阴影，选项之间留 10px 间距 |
| 解析 | 展开时和 Angular 的折叠动画打架，会闪 | 自建面板，默认折叠，头部带「复制题目」「询问 AI」「解析和展开」 |
| 答题卡 | 原生 | 右上角自制悬浮答题卡（原生答题卡移出屏幕，跳转逻辑保留）；**没有题目时整张卡不显示** |
| 自定义刷题 | 出题数量只有 5/10/…/40 八档 | 那一行的第一格（`5`）变成输入框，1–500 任意填，改完弹一条带「刷新」按钮的提示 |
| 下载按钮 | 直接下载成册的 PDF | 点一下弹菜单：**题目成册**走原功能，**题目脱库**把当前这套练习导成 `.md` + `.json` |

### 拦截接口，一次拿全

背题页的解析数据来自 `tiku.fenbi.com/combine/static/solution`。这个接口**一次性返回整份练习所有题目的** `solution` / `source` / `keypoints` / `correctAnswer`。

其中 `correctAnswer` 是个**对象**，而且答案给的是下标不是字母（实测自一套 50 道题的练习）：

| 题型 | `correctAnswer` | 怎么读 |
|---|---|---|
| 单选 / 多选 / 不定项 / 判断 | `{choice: '3', type: 201}` | `choice` 是选项下标的逗号串，`'3'` = 第 4 个 = D；多选 `'0,1,2,3'` = 全选 |
| 填空 | `{blanks: ['讲授'], type: 202}` | 每空一个答案 |

下标顺序和页面选项的 A/B/C/D 是不是同一个顺序，这件事只能实测 —— 对不上的话导出来是一份看着很像样、其实全错的答案。验法是拿接口的 `accessories[0].options` 和页面上读到的选项逐条比：那套数据里 42 道选择题**全部一致**，另外 8 道（判断题）接口不给 options。

脚本在 `document-start` 同时挂钩 `XMLHttpRequest` 和 `fetch`，把这份响应抄下来存进 `Map`。`globalId` 和页面上 `app-ti[data-question-key]` 一一对应，所以能精确地把数据挂到对应题目上。

> 为什么不自己发请求？因为 URL 里的 `key` 参数不在页面 HTML 里，由粉笔的前端运行时生成，脚本无法复现。挂钩是唯一可靠的办法。

### 自建解析面板

粉笔对每道题的解析区是**懒渲染**的：你没点过的题，`app-result-common`、`app-solution-overall` 这些节点根本不在 DOM 里，连正确答案的高亮都没有。点完选项之后 Angular 才去渲染，这就是卡顿的来源。

脚本改为在每题的 `.ti-container` 里挂一个自己的 `.fb-sol-panel`，内容全部来自缓存。面板默认隐藏，在 `document` 上用捕获阶段的 `click` 监听选项，点到就立刻加 `.fb-sol-visible` —— **抢在 Angular 前面**，不等网络也不等渲染。

同时把原生 `app-result-common` 整块隐藏（里面只有 video / solution / keypoint / source / note，全是这个脚本本来就要隐藏的），页面上只留一套解析 UI，不会再出现“闪一下再折叠”。

### 修掉一个自我触发的重排死循环

这是卡顿的真正技术原因，也是 2.0 最大的改动，值得单独说：

原版脚本里 `updateCustomCard()` 每一轮都会无条件写 `count.textContent = ...`。而写 `textContent` 会移除旧文本节点、插入新节点，**产生新的 mutation**；MutationObserver 又正好监听 `document.body` 的 subtree，于是再次触发自己。结果是：

```
写入 → mutation → observer(150ms) → 全页重扫 + 80 次 innerText 强制重排 → 写入 → ...
```

一个永动的 150ms 循环，每轮都在一个 700KB 的 DOM 上强制同步布局。

2.0 做了三件事断掉它：

- **所有写操作先比对再写**：`setText()`、`important()`（比对 `getPropertyValue` + priority）、`classList.toggle(name, force)`。值没变就不碰 DOM，不产生 mutation，循环自然收敛。
- **热路径里删掉全部 `innerText`**：`innerText` 会强制同步重排，改用 `textContent`。
- **冷热分离**：`optimizeDynamic()`（面板同步 + 答题卡）跟着 mutation 走；`optimizeQuestionWidth` / `optimizeOverall` / `hideVipModules` 降级为 1.5 秒一次的低频兜底——这些选择器 CSS 本来就全覆盖了。

另外 `getCurrentQuestionIndex()` 的几何回退要读 40 次 `getBoundingClientRect`，加了 250ms 缓存，不再每次 mutation 重算。

### 三栏是按比例切的

屏幕横向切成三栏 —— **AI 面板 | 答题区 | 答题卡**。前两栏按上面的百分比走，答题区吃剩下的那份（没有第三个配置项：写出来就有三份数，改两个忘一个的时候谁也不知道该信哪个）。

比例相对的是视口，所以同一个比例在整个屏幕上都成立。以前是三个写死的 px 数，`380px` 在 1920 上占两成、在 1280 上占三成，「占多宽」跟着屏幕悄悄变，而答题区的让位量又是第三条式子 —— 改了一边就压到题目上。

答题区的几何只有一处：

```js
const AI_COLUMN   = `max(${CONFIG.aiPercent}%, ${CONFIG.aiMinWidth}px)`;
const CARD_COLUMN = `max(${CONFIG.cardPercent}%, ${CONFIG.cardMinWidth}px)`;

const QUESTION_INSET_LEFT  = `calc(${AI_COLUMN} + ${CONFIG.panelLeft}px + ${CONFIG.columnGap}px)`;
const QUESTION_INSET_RIGHT = `calc(${CARD_COLUMN} + ${CONFIG.cardRight}px + ${CONFIG.columnGap}px)`;
```

让位量引用的是**栏宽那两个表达式本身**，所以下限一触发两边一起动，不会出现「面板还按 22% 缩、答题区却按别的让位」那种错位。答题区那边 `width: auto` + 两条 margin —— 让出多少由 margin 说了算，宽度自己就是剩下的那些，不用再把同一件事算两遍。

`max()` 是「百分比，但不小于下限」：900px 的屏上答题卡按 15% 只有 135px，减掉四周留白剩 87px，题号会挤成一列 —— 名义上按占比了，实际上不能用。

**答题区没有宽度上限。** 原来是 `max-width: 900px`，宽屏上拉到 900 就停，三栏的占比在宽屏上其实不成立。撤掉它得同时显式写 `max-width: none` —— 粉笔自己给 `.memorize-main` 写了 `max-width: var(--screen-width)`（桌面是 `100vw - 260px`），原来是我们那条 `!important` 压着它，撤掉就冒出来了。

换来的代价说清楚：**1600px 以下的屏幕上答题区比以前窄**（AI 面板现在真的占掉一栏，以前它浮在题目左边），1600px 以上比以前宽。1920 上是 1140px（原来 900），1440 上是 838px（原来 900）。

一段典型的实算（1920 屏、15px 滚动条）：

| | AI 面板 | 答题卡 | 答题区 | 左缝 | 右缝 |
|---|---|---|---|---|---|
| 2560 | 563 | 384 | 1543 | 10.7 | 26.8 |
| 1920 | 422 | 288 | 1140 | 10.7 | 26.8 |
| 1440 | 317 | 216 | 838 | 10.7 | 26.8 |
| 1000 | 260 | 180 | 485 | 14.0 | 29.0 |

缝不是正好 14px：三栏的百分比是相对视口算的，而答题区让位用的是它自己包含块的百分比，两个基数差一个滚动条的宽度。这点误差落在缝里，不会让哪两栏真贴上 —— 上面那几档左右缝都是正的。

750px 以下三栏排不下，退回两栏（答题区占满、答题卡浮在上面，见媒体查询）。中间那一档（≤1000px）删掉了 —— 它原来是把卡压到 195px、让答题区让出 220px 的一对手写死的数，现在百分比自己会缩到下限，不用再单开一档。

### 一行几个题号：从实测宽度算

以前是 `CONFIG.columns = 5` 写死的。卡放宽了还是 5 列 —— 每个格子白白变胖；卡被媒体查询压窄了还是 5 列 —— 格子就挤了。2.6 起改成从题目区的实测宽度算：

```js
const columns = Math.floor((width + gap) / (minCellWidth + gap));
```

宽度靠 `ResizeObserver` 拿，**不在 mutation 的热路径里** —— 这份脚本被「自我触发的 150ms 重排循环」咬过一次，热路径里每轮读几何尺寸正是当初的病根。

量的是 `getBoundingClientRect().width`（边框盒），**不是 `clientWidth`**。题号多了会出滚动条，`clientWidth` 要减掉滚动条宽度，于是「出现滚动条 → 少一列 → 内容变矮 → 滚动条消失 → 多一列 → …」来回抖。边框盒不含滚动条，反馈回路从根上不存在。

（也没用 `scrollbar-gutter: stable` —— 那会永久窄掉一块内容，默认的 5 列就会变成 4 列。）

### 内边距和卡宽的下限是一对

题号区实宽 = 卡宽 − 2（面板边框）− `.fbac-body` 内边距 × 2，而这个实宽决定一行几个题号。

卡宽现在是百分比，所以「默认卡宽」这个概念没有了 —— 但有**下限**，那是它最窄的样子。下限那组数是：

```
180 − 2 − 24 × 2 = 130  →  floor((130 + 7) / (33 + 7)) = 3 列
```

下限再往下调、或者单独把 `.fbac-body` 的内边距调大，最窄的卡就排不满三列了 —— 页面上不会报错，只是题号格突然变少一排的样子。

（老版本那个 256px 的卡排 5 列，算式是 `256 − 2 − 24 × 2 = 206`。留白加过两轮，实宽一直是 206：`11 → 16 → 24` 配 `220 → 240 → 256`，每一次都是「卡宽加多少、内边距就吃多少」。现在宽屏上卡更宽、列数更多，那个 206 只在下限那一档成立。）

`test/card.test.mjs` 里有一条断言把这个算式钉住了：它同时校验 `cardMinWidth` 的推导值和 CSS 里 `.fbac-body` 的 `padding`，改其中任何一个都会红。

### 题号区自己还有一圈 5px

上面那层 `.fbac-body` 的 24px 是卡片四周的留白。题号区自己还留了一圈，写在 `.fbac-grid` 上：

```css
padding: 5px;   /* 上下左右都是 5 */
```

这圈是给**阴影**留的，不是给视觉留白留的。`.fbac-grid` 是 `overflow-y: auto` 的滚动容器，而滚动容器的裁剪边是 padding box —— 一点 padding 都不留的话，第一列题号选中时的光圈（`.is-current` 那条 `box-shadow` 往外支 2px）和 hover 时上浮的 1px 会被切掉一条边，看着就是题号贴在了卡片边上。5 比光圈和上浮都宽，四边都留就都盖住了。

原来只有左 2（光圈宽度）和上 5（光圈 + 上浮），右边靠滚动条顶开、下边干脆没留。2.12 改成四边一致 —— 只有一两边有留白的时候，底下那排题号贴着卡片下沿，看着像是被截断了。代价是右边那 5px 和滚动条叠在一起，题号区窄了一点。

**这圈 padding 有个隐蔽的地方**：它吃的是 grid 的 content 宽度，而 `syncCardColumns` 量的是 `getBoundingClientRect().width`，也就是 border box —— `box-sizing` 是 `border-box`，量出来仍是 206，**量不到被 padding 吃掉的那部分**。所以它一大，报出来的列数还是 5，格子却在悄悄变窄，最后挤成一条，而且没有任何一处能量得出来。

`test/card.test.mjs` 里另有一条盯着它：既校验 CSS 里的 `padding` 值，也拿 `206 − 5 × 2` 实算一遍列数。

### 题目多了自己滚

卡片有 `max-height: calc(100vh - cardTop - cardBottom)`，超出部分**由题号那一格自己滚**，标题行、状态行、底部「当前：N」都不动。

不给滚动的话题目一多卡片就一路长到屏幕外面，那三行正是滚动时最该一直看得见的。实现上是卡壳 → `.fbac-panel` → `.fbac-body` → `.fbac-grid` 一条竖向 flex 链子，中间两层都写了 `min-height: 0` —— flex 子项的默认最小高度是内容高度，少写一处底下那个 `overflow-y` 就永远不触发，而且页面上看着完全正常，只是滚不动。

### 没题目就不显示

答题卡原来是不问青红皂白就挂在页面上的 —— 目录页、解析页、首页这些地方没有题目，卡片上只剩「0/0」「共 0 题」，白占一块地方还压着底下的内容。

现在**没有题号就把整张卡收起来**。判据用的正是这张卡要显示的东西：粉笔原生答题卡里 `.answer-btn` 有几个。一个都没有就是没数据 —— 要么题还没加载出来（那就等它加载好再露），要么这一页压根不是答题页。

这也是它唯一会出现的方式：卡片建出来时就是藏着的，之后每轮 `updateCustomCard` 按题号数量决定露不露。粉笔是单页应用，从答题页点回目录页走的正是同一条路，卡片跟着收起来，不用另接路由。

实现上踩到两个坑，都记在这儿：

**一、隐藏规则必须写成 `display: none !important`。** 卡片自己那条 `#fenbi-custom-answer-card` 把 `display` 钉成了 `flex !important`，而 CSS 是**先比重要性、再比特异性** —— 一条不带 `!important` 的类选择器根本盖不住它。表现是「隐藏类加上了，卡片照样杵在那儿」，而且一点报错都没有。`test/card.test.mjs` 里有一条专门盯着这个感叹号。

**二、从藏变露那一次得重量一遍宽度。** 藏着的时候 `display: none` 没有盒子，`getBoundingClientRect()` 量出来是 0 宽，`computeColumns` 会把 0 兜成 1 列。不重量的话卡片会先以 1 列的样子画出来，等 `ResizeObserver` 下一轮回调才跳回 5 列 —— 一眼能看见的闪。所以 `applyCardVisibility()` 的返回值特意区分了**「这一下刚露出来」**和**「一直露着」**：只有前者才需要重量，后者每轮都量等于把热路径又拖回读几何尺寸的老路上。

### 层级：两个助手得压在同一档上

现象是点「暂停答题」之后，粉笔那层半透明遮罩**盖得住 AI 面板、盖不住答题卡** —— 满屏灰里独独浮着一张答题卡。

这个坑分两层，第一层修错了，值得完整写下来。

**第一层（错的判断）**：看着像两个助手的 `z-index` 差了一位，于是把两边调成同一个数。**没用。**

**第二层（真身）**：粉笔的遮罩是 `DIV.modal-overlay`，`position: fixed`、`z-index: 1000`、盖满屏幕、`rgba(0,0,0,0.5)`。而侧边栏的**宿主元素**压根没有 `z-index`（是 `auto`）—— 宿主是 `position: fixed`，本身就是一个层叠上下文，所以 shadow 里 `.wrap` 那个再大的数也只能在宿主内部排序，对外整个面板仍然停在 `auto` 那一档。

于是浏览器看到的实际是：

| | 实际排在哪一档 | 遇到遮罩（1000） |
|---|---|---|
| 侧边栏 | `auto`（宿主没设 z-index） | 在下面 → **盖得住** ✓ |
| 答题卡 | `2147483646` | 在上面 → **盖不住** ✗ |

一个在 `auto` 档、一个在正数档,**这两个数根本没法比** —— 所以「把两边调成同一个数」这条路走到黑也修不好。面板被遮住跟它那个数字毫无关系。

**修法**是两件事一起做：给宿主补上 `z-index`，再把两边都压到遮罩之下、仍在粉笔页面元素之上。取值区间是：

```
500  —— 粉笔页面元素里最高的那个（--z-index-footer）
900  —— 两个助手
1000 —— 粉笔「暂停答题」的遮罩
```

比 500 低会被页脚那类东西压住，比 1000 高就浮到遮罩上面去了。

**测试守的也从数字改成了关系。** 原来那条钉的是 `zIndex === 2147483000` —— 数对了、关系是错的，答题卡照样浮在遮罩上，测试却一直绿着。现在断言两条：宿主必须自己带 `z-index`（`test/panel.test.mjs` 里真的 `boot()` 起来读宿主元素），以及两个助手的值必须落在 500 和 1000 之间。

### 「下载」按钮：点一下弹菜单

答题界面上那个下载按钮现在弹一个小菜单，两项：

| | 做什么 |
|---|---|
| **题目成册** | 就是原来那个功能 —— 把这一套题排成册子下载 |
| **题目脱库** | 把当前这套练习导成两个文件：`.md`（可读）和 `.json`（接口原样数据） |

拦截挂在 `document` 的**捕获阶段**，并且 `preventDefault` + `stopPropagation` + `stopImmediatePropagation` 三件套齐全。少任何一件，粉笔自己的 Angular 监听照样会跑，文件照样下下来，而从页面上完全看不出脚本没生效 —— 这是这类「把默认行为拿过来自己做」的写法最容易骗过自己的地方。

**「题目成册」为什么要重放一次点击。** 我们的守卫挂在捕获阶段，拦得比粉笔自己的监听还早；而 Angular 的处理器是绑在它自己那批节点上的，没有可以「调用一下原函数」的入口。所以走的是**举旗子 + 重放**：置一个 `downloadBypass`，再 `dispatchEvent` 一个合成 `MouseEvent`，守卫看到旗子就放行。`dispatchEvent` 是同步的，所以 `finally` 里复位旗子不会漏 —— 漏了的话，从此点下载按钮会直接触发粉笔的下载，菜单再也不弹。

**重放派给的是「用户当时点的那个元素」，不是 `app-download` 那个宿主。** 这两者不一样：守卫认的是 `closest('app-download')`，那是宿主；而真人点的是它里头的图标。事件只沿**派它的那个元素**往上冒 —— 派给宿主的话，传播路径是 `document → … → app-download`，挂在它**子孙**上的监听压根不在路径上，一个都不会响。粉笔的处理器挂在宿主上还是挂在图标上只有运行时知道，照着真人的样子来两种都盖得住（真点宿主时两者本来就相同）。

重放这一下有个前提：粉笔那边不能查 `event.isTrusted`。查了的话合成事件会被拒掉，表现是点「题目成册」什么都不发生，而且不报错。

**菜单挂在 `body` 上，不挂在 `app-download` 里。** 挂进去的话，点菜单项那一下 `event.target` 落在 `app-download` 内部，会被守卫当成「又点了一次下载」吃掉。

#### 题目脱库：数据来自两个地方，各占一半

| | 从哪来 | 为什么 |
|---|---|---|
| 题干 / 选项 | **DOM** | 接口那份里根本没有题干 |
| 答案 / 解析 / 来源 / 考点 | **拦截下来的接口缓存** | 页面上只渲染已作答的题，没答过的在 DOM 里这几块压根不存在 |

所以**缓存是空的时候不导出**，只弹一条提示。实测一套 5 道题的练习里只有 2 道在 DOM 里带着解析 —— 缓存空着导出去的就是一份只有题干、没有答案也没有解析的空壳，而文件本身完全看不出来少了什么。

答案那一栏是接口给的**下标**（`{choice: '3'}`），要翻成字母才对得上选项。翻的时候用的是**这道题自己的选项表**：字母优先取页面渲染的那个，页面没给就按位置数 —— 判断题那对「正确 / 错误」在页面上压根没有字母（`label` 是空串），只认页面的话这一整个题型导出来都是没答案的。下标要是越出了选项个数就原样留着数字不编字母，编出来的那个看着完全正常，而它是错的。

文件名是「页面标题 + 时间戳」，标题取 `.header-title`（先读 `title` 属性再读文本，都没有就退回 `document.title`）。标题里的 `\ / : * ? " < > |` 和空白一并压成 `_` —— 题目来源恰好就爱写「2025年4月26日 10:30」这种东西，而**冒号在 Windows 上是非法字符**。

`.json` 里每道题还有一个 `api` 字段，是**接口原样返回的那个对象**，上面那些字段都是给它做的翻译。翻译就会丢东西 —— 想做别的处理（错题本、按考点归类）不用再爬一遍接口。

### 自定义刷题：任意出题数量

在 `www.fenbi.com/spa/tiku/guide/catalog` 的「自定义刷题」弹窗里，出题数量那一行的**第一格**（原来那个 `5`）变成一个输入框，可以填 1–500 之间的任意整数。10 / 15 / 20 / 25 / 30 / 35 / 40 都不动。

**代价是 `5` 这个预设没了**，要 5 道得自己敲。之所以顶掉第一格而不是在末尾加一格：八个小方块那一行本来就是满的，第 9 格会把行撑爆，和旁边几个方块摆在一起一眼就是硬塞进去的。

那个 `5` 是**藏起来**，不是从 DOM 里删掉 —— 它是 Angular `*ngFor` 渲染的，身上挂着粉笔自己的点击监听，从人家的清单里挖掉一个节点，下一轮重建时对不上。留着它、只是 `display: none`，粉笔那边完全不知道自己少了一格。

#### 这个数怎么送出去：改请求，不碰 Angular 的状态

克隆一个原生按钮下来是走不通的 —— 样式对、点击没反应，因为 Angular 的监听挂在它自己那批节点上。正路本来是顺着 `__ngContext__` 摸到组件实例，但那长什么样只有运行时才知道。所以**没有猜，先量了一遍**，探针量出来这个数就在请求的 query 里：

```
POST //tiku.fenbi.com/activity/userquiz/updateUserQuestionInfo
     ?sheetType=151&questionCount=5&yearScope=5&...
```

看 `questionCount` 那一段 —— 在 **query 参数**里，不在 body。按 body 字段猜的话会一直改不到，而且一点报错都没有。

于是链路是：

```
输入框 → pendingCustomCount → 网络钩子出站前换掉 query → 作废
```

XHR 那一头在 `open()` 里换，**不是 `send()`** —— `open` 是 URL 最后还能改的地方，到了 `send` 请求行已经定死，那时候改只是改给我们自己看的（代码在、日志也在、数量纹丝不动）。fetch 那一头同样在出站前换，`input` 是 `Request` 对象时得重新包一个 —— 直接把字符串顶上去会把 method / headers / body 全丢掉，那比不改还糟。

#### 什么时候作废

这个数**只用一次**，两条作废规则各自都必要：

**一、换到了就作废。** 模态框会被 Angular 重建，我们那个输入框跟着一起没，但这个数不会 —— 留着的话，下次打开模态框随手点「保存」，发出去的是上一次敲的数，而屏幕上那个输入框早就不在了，没有任何地方看得出这个数是从哪儿冒出来的。

顺序也不能反：**先判有没有换到、再作废**。反过来写的话，页面上随便一条埋点请求都能把这个数吃掉 —— 用户敲完 10、保存时却变回预设，而埋点请求在 Network 面板里根本不会有人去看。`test/count.test.mjs` 里有一条专门盯着这个顺序。

**二、点了别的预设也作废 —— 预设优先。** 不作废的话：敲了 10、又改点「20」，保存下去的还是 10，而屏幕上亮着的是「20」。页面说一套、发出去另一套，两边单看都是对的。

认的是 `a.select-button` 而不是 `.select-button`：我们自己那个输入框也带着 `select-button`，但它不是 `<a>`，写成后者的话在输入框里点一下就把自己作废了。

#### 改完之后那条提示

换掉的只是**发出去的那个请求**。当前页面上这套题是照旧数量推下来的，不会因为一条请求就变 —— 用户敲完 10、点保存，界面纹丝不动，看着就是没生效，而它其实生效了，只是要刷新才看得见。

所以换到之后在屏幕右下角弹一条：

> 出题数量已改为 10，刷新后生效　[刷新]　×

带一个「刷新」按钮，点了 `location.reload()`。给 12 秒（比普通提示的 8 秒长，因为它带一个要用户动手的按钮）。

这条提示的层级是 `CONFIG.toastZ = 1001` —— **全脚本唯一一个故意高过模态层的数**。上面那条「不许高过 1000」的规矩对它不适用，因为它恰恰是在粉笔自己的模态框里点完「保存」之后弹出来的：压到 900 的话它就在模态遮罩底下，一个字也看不见，等于没提示。代价是「暂停答题」的时候它会浮在遮罩上面 —— 认了，它自己会走，而且只在刚点完保存那几秒里存在。

提示里任何一步出错都不可能连累请求：换 URL 在弹提示之前就已经成功了，那两句 `announceAppliedCount()` 都裹在 `try` 里。不裹的话，提示里随便哪儿抛出去都会顺着钩子传回粉笔的请求链，页面上**每一个** XHR 都发不出去。

## 三、豆包端自动填写

跑在豆包页面里。粉笔那边的脚本够不到跨域 iframe 里的输入框 —— 那是一堵墙。唯一能碰豆包输入框的，是跑在豆包页面自己里面的脚本，也就是这一个。

收到题目后：找输入框 → 填进去 → **自动发送**。

### 找输入框：按几何特征，不按 class

豆包的 class 是一长串 Tailwind 工具类加一个带哈希的后缀（比如 `enhanceBtn-W9xBoi`），改版就换一批，认不住。所以按形状认：**面积最大的那个可编辑区域**，面积相同取更靠下的。同时排除上半屏（那是对话记录）、隐藏的（富文本编辑器常留一个隐藏 textarea 兜底）、太小的。

### 发送：按位置认按钮，加上硬性半径

同理不认 class。发送按钮唯一稳的特征是**在输入区的右下角** —— 这个位置关系由「人手够不够得着」决定，不是哪个前端随手写的。

三层筛：

1. 在输入框横向中点**右边**（左边那排「深度思考」「联网」点了会改设置）
2. 在输入框顶边**以下**（上方是对话记录和它的操作按钮）
3. 距输入框右下角 **160px 以内**

取最近的。那个半径是有意加的硬上限：**选不中顶多发不出去，选错了就是在你的页面上乱点按钮**。超过半径就不点，退回模拟回车。

填完等 250ms 再发 —— 富文本编辑器把内容同步进自己的状态要一个 tick，早了发送按钮还是灰的，点了没反应而且是静默的。

发完 900ms **回头验一眼编辑器空了没有**。点下去和真发出去是两件事，不验的话「点了但没生效」会一路装成成功。没清空就弹提示，并在控制台打一张周边按钮的表。

### 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `autoSend` | `true` | 填完自动发。改成 `false` 就只填不发 |
| `sendDelay` | `250` | 填完等多久再发（ms） |
| `sendVerifyDelay` | `900` | 发完等多久回头验（ms） |
| `allowedOrigins` | 粉笔三个域 | 只认这些来源发来的消息，**没有通配符** |
| `searchFrom` | `0.4` | 只在下 60% 找输入框 |
| `waitTimeout` | `12000` | 等输入框出现的上限（ms） |
| `hideTexts` | `['下载电脑版']` | 顺手藏掉的按钮，按文字认 |

### 页面上的测试入口

脚本跑在页面上下文（`@grant none`），所以控制台直接敲得到：

```js
fbaiTest()              // 单独测「找输入框 + 填入 + 发送」
fbaiFill('题目原文')     // 拿真题试，跳过拼接
fbaiDump()              // 打印输入框周边所有按钮，按离右下角的距离排序
```

`fbaiDump()` 是发不出去时用的：`距右下角` 那一列最小的、又不带「禁用」的，就是真的发送按钮。

还有 `Ctrl+Alt+F`（Mac 上是 `Ctrl+Option+F`）快捷键，但控制台那条更稳 —— 三键组合有可能被浏览器或输入法先吃掉，吃掉了还不报错。

## 四、去头扩展

ChatGPT、豆包这些站点都发了 `X-Frame-Options` / `Content-Security-Policy`，禁止自己被别人 iframe 嵌进去。所以要嵌进粉笔页面，得先把这两个响应头去掉。

装在 Chrome 里的 MV3 扩展，用 `declarativeNetRequest` 改响应头。**作用范围是收窄的**：

```json
"resourceTypes": ["sub_frame"],
"initiatorDomains": ["fenbi.com", "localhost"]
```

只有**由 fenbi.com 页面发起的子框架请求**才会被改。不影响你正常访问这些站点，也不影响别的网站嵌它们。

> ⚠️ 这个扩展的用途就是关掉目标站点的防嵌入保护。它的权限清单里列了 13 家 AI 站点的域名。**只在你自己的浏览器上、为了这个用途装**，测完不用了就禁用掉。

## 五、手柄操作

躺床上刷题时不想摸键鼠。装 `fenbi-gamepad.user.js`，整套流程用手柄走完。

**先按一下手柄上的任意键。** 浏览器出于隐私考虑，在你按过键之前 `getGamepads()` 一直返回空 —— 插着不动等于没插。按一下，左下角会出现一个「🎮 手柄名」的角标，那就是认出来了。这一步是「脚本是不是坏了」最常见的误判来源。

### 默认键位

| 手柄 | 干什么 |
|---|---|
| 十字键 ↑ / ↓ | 移选项光标（按住连发） |
| 面键 1（下面那个） | 确认，选中光标停的那一项 |
| LT（左扳机） | 提交（多选题、不定项选完要点「确定」） |
| 十字键 → / ← | 下一题 / 上一题（按住连发） |
| 左摇杆 ↑ / ↓ | 上滚 / 下滚 |
| LB（左肩键） | 展开 / 收起解析 |
| RB（右肩键） | 跳题（弹一张题号表） |
| RT（右扳机） | 询问 AI（把当前题递给左侧面板） |
| Start 短按 | 开关左侧的 AI 面板 |
| Start 长按 1 秒 | 交卷 |
| Back 短按 | 打开手柄设置 |
| Back 长按 1 秒 | 回退网页 |
| 左摇杆按下（L3） | 回退网页 |
| 右摇杆按下（R3） | 交卷 |

键位**全部可以改**：油猴菜单 →「手柄设置…」，或者短按 Back 一下。

**一条绑定 = 一个键 + 一种按法。** 面板里每一行是一个动作，行里列着它自己的键：`按钮 11 ✕` 是短按，`长按 按钮 9 ✕` 是按住一秒。想加一条就选好「短按 / 长按」再点「录入按键」，然后按下手柄上那个键。截图里的「交卷」那一行就是这样两条 —— 短按 R3、长按 Start，两件事都写在交卷自己这行，不挂在别人身上。

**同一个键可以给两个动作用，只要一短一长。** 同一个键上的两件短按（或两件长按）会互相顶掉，**后录的赢**，被顶掉的那条直接从面板上消失。录完提示会写明落到谁头上（「按钮 0 → 下一题」）。按住本来就连发的动作（移光标、翻题、滚动）是例外：那一档按住就是连发，整个键都是它的，挤不下第二件事。

改完当场生效，不用刷新。

**每个动作都只是「点一个 DOM 元素」。** 没有哪一个是特殊的 —— 包括开关 AI 面板（点侧边栏头部那个收起键，收起后点边上常显的小标）和交卷（点那个 `div.submit-btn`）。所以哪个动作不灵了，看一眼页面就知道是哪个按钮没找到，不用去猜是不是两脚本之间的暗号没对上。

### 几件要知道的事

- **答完即锁。** 一题只有一次机会，点下去就定了。所以选项是「移光标 + 确认」两步：多选题要勾几个就勾几个，超过四个选项的题也照样能选（直选做不到这个）。
- **交卷和回退网页默认都做得难按**：自己的键在摇杆下压（L3 / R3）上，不在面键上；另外还各藏在一个长按里（Start→交卷、Back→回退）。这两个都不可逆 —— 交卷交掉整份，回退丢掉这套练习的进度 —— 而摇杆下压要刻意使劲，聊天时误触不了。
- **交卷的确认框手柄也能用。** 粉笔点完交卷会弹一个「确认交卷?」，十字键 ↑↓ 在「取消 / 确认」之间挪，面键 1 按下去。弹窗开着的时候只有这几个键有效，别的动作一律不理（不然就是隔着一层弹窗把底下的题答了）；Back 键是「取消」，不是退回上一页。**光标默认停在「取消」上** —— 交卷不可逆，连按两下最多是取消。
- **不装布局脚本也能用**，选选项、翻题、滚动、交卷、回退走的都是粉笔原生 DOM。但有两个动作要装了才有：**展开/收起解析**和**询问 AI** —— 它们点的是布局脚本自建解析面板上的按钮，没装就没有那个按钮。
- **按了没反应时先看控制台。** 油猴菜单里有一项「手柄调试日志」，打开之后每一次按键都会打一行 `按键 → 动作`；展开和询问 AI 找不到目标时也会打一行说明原因（是题号找错了，还是这一题的解析面板还没建起来）。
- **不做填空题。** 手柄打不了字，遇到填空题静默跳过。
- **震动只有 Chrome / Edge 有**（`vibrationActuator` 是它们的私有实现）。答对震两下短的，答错震一下长的，总时长不超过 0.5 秒。
- **键位是按「索引」认的，不是按 A/B/X/Y。** 索引 0 是「下面那个键」—— Xbox 上叫 A、PS 上叫 ×、Switch 上叫 B。换个手柄名字就全反了，所以设置面板里能用索引重新绑。手柄报的不是标准映射时，面板会明说。

### 为什么不用合成键盘事件

这套东西全程直接操作 DOM，一个 `KeyboardEvent` 都不发。发合成事件的话，会跟页面和另外两个脚本的现有快捷键（比如 AI 面板的 Alt+Q）撞车，而且谁先跑取决于监听顺序 —— 出了 bug 极难查。

### 当前题号是怎么认的

手柄得知道「现在在哪道题」，不然选选项会选到别的题上。三个来源，优先级从高到低：

1. **布局脚本写在 `data-fbai-current-question` 上的值。** 它本来就在算这个。
2. **手柄自己翻的题。** 布局脚本那个属性有 250ms 缓存，而连发间隔才 80ms —— 快翻的时候属性还没跟上。所以手柄记着自己翻到了哪，并且盯着属性：属性一从「翻之前那个值」变成别的，就说明布局脚本追上了，交还给它。
3. **35% 视口启发式。** 没装布局脚本时的兜底。

> 布局脚本只在它渲染答题卡的时候调那个函数，所以属性是答题卡出来之后才有的。之前走第 3 条 —— 真机上启发式是准的。

## 六、「询问 AI」这条链路，为什么绕这么大一圈

点击解析面板上的「询问 AI」，题目会出现在豆包的输入框里并被自动发送。中间隔了三堵墙：

```
粉笔页面                                    豆包页面（iframe / 独立窗口）
┌─────────────────────────────┐
│ 布局脚本                     │
│   ├─ 把题目写进 DOM 属性      │
│   └─ 派发 fbai-ask 事件       │
│          ↓                   │
│ 侧边栏                       │
│   └─ postMessage ────────────┼──────→  ai-autofill
│                                          ├─ 找输入框
│      ← data-fbai-ask-result ─┼──────────┘ ├─ 填入
│         （结果码）             │            └─ 发送
└─────────────────────────────┘
```

**两个脚本各在自己的油猴沙箱里，看不到对方的变量，也调不了对方的函数。** 能共用的只有 DOM。所以：

- 题目写在 `documentElement` 的 `data-fbai-ask` 属性上，配一个 `fbai-ask` 事件通知
- 侧边栏处理完，把结果码写回 `data-fbai-ask-result`，布局脚本读出来决定按钮上闪什么字
- 用**属性 + 普通 Event**，不用 `CustomEvent.detail` —— 跨沙箱传 detail 不稳，属性是两边都看得见的普通 DOM

这套东西有个特点：**改了一边忘了另一边，表现是「点了没反应」，没有任何报错，页面上也没有线索。** 所以有一整组测试专门盯着「两边名字一致」：

```js
assert.equal(layout.ASK_EVENT, sidebar.CONFIG.askEvent);
assert.equal(layout.ASK_ATTR, sidebar.CONFIG.askAttr);
assert.equal(sidebar.CONFIG.askTag, autofill.CONFIG.messageTag);
```

跨域那一步用 `postMessage`，**目标 origin 写死成 `https://www.doubao.com`，不是 `*`** —— 用 `*` 的话任何嵌进来的页面都能收到这条消息。

送不出去的时候（选的是 ChatGPT 这类没有配套脚本的站点），题目退回剪贴板而不是静默丢掉 —— 静默丢掉是最差的，用户会以为脚本坏了，而其实题目就在手边。

面板收起来的时候题目来了会自动弹回来，不然填进去了也看不见。

## 开发与测试

```bash
npm install
npm test
```

277 个用例，跑在 Node 内置的 test runner + jsdom 上。

**测的是要发布的代码本身，不是它的副本。** 三个脚本都是单文件、无构建，出口长这样：

```js
if (typeof module !== 'undefined' && module.exports) {
    module.exports = { /* 纯函数和常量 */ };   // Node：跑测试，一行 DOM 不碰
} else {
    start();                                  // 浏览器：按原样启动
}
```

所以改完 `.user.js` 直接 `npm test` 就行，没有构建步骤。

```
ai-autofill.user.js            纯函数、几何启发式、编解码、来源校验
fenbi-ai-sidebar.user.js       面板行为、菜单、投递目标决策
fenbi-memorize-layout.user.js  复制题目、布局常量、答题卡列数、下载菜单、脱库导出、自定义数量
fenbi-ai-unframe/              扩展
test/
  harness.mjs                  在 jsdom 里把侧边栏真跑起来的共用夹具
  make-fixture.mjs             从题库存档生成测试夹具
  panel.test.mjs               面板行为，以及「和答题卡统一」的跨脚本比对
  card.test.mjs                答题卡的列数算法与滚动
  download.test.mjs            下载拦截：判定 + 真起一个 DOM 验事件传播顺序
  count.test.mjs               自定义出题数量的解析、注入与改完之后的提示
  export.test.mjs              「题目脱库」：DOM 那一半 + 接口那一半 + 拼出来的文件
  *.test.mjs                    277 个用例
```

`card.test.mjs` 和 `count.test.mjs` 里都要从源码里抠 CSS 声明块或纯函数来断言。抠 CSS 的时候**不能用 `/\{([\s\S]*?)\}/`** —— 模板字符串里的 `${CONFIG.xxx}` 自带一个花括号，非贪婪匹配会正好断在那儿，于是「块里没有 `overflow-y`」这种**假失败**就出现了。`card.test.mjs` 的 `cssBlock()` 两头都认缩进，就是为这个。

jsdom 不做排版，`getBoundingClientRect` 恒等于 0，所以「按形状 / 位置挑元素」那几段逻辑，测试里得自己把矩形塞进去（`test/autofill.test.mjs` 里的 `candidate()` 和 `place()` 就是干这个的）。测量和挑选因此是分开的两个函数 —— 挑的那半是纯的，好测。

**测试夹具不含题库内容。** `test/make-fixture.mjs` 在你本地从 `*背题.html` 存档生成 `test/fixtures/`，两者都在 `.gitignore` 里，不随仓库分发。

## 常见问题

**Q：解析没出来 / 面板是空的？**
先看控制台有没有 `接口解析缓存` 那条日志。没有的话说明接口拦截没命中——可能是粉笔改了接口路径，改 `API_KEYWORD` 常量即可。

**Q：刷新之后解析全都不见了？**
2.1 已修。2.0 的面板只认“本次加载里点过选项”，刷新把状态清零就会满页空白。现在已答的题会自动显示解析入口。

**Q：解析入口什么时候显示？**
三种情况任一即可：点过该题选项、该题已作答、该题是填空题。除此之外保持折叠，正文要手动展开。

**Q：接口挂了脚本会整个失效吗？**
不会。保留了 DOM 兜底：缓存没命中时退回抓原生 `section-solution` / `section-source` / `section-keypoint`。只是这种情况下又会回到“粉笔渲染过才有”的老行为。

**Q：点了「询问 AI」没反应？**
按这个顺序看：

1. 控制台有没有 `[粉笔 AI 侧边栏] 收到询问请求` —— 没有就是侧边栏没装或装的是旧版（看启动日志里的版本号）
2. 下一行 `投递结果：sent / copied / none` —— `copied` 说明退回剪贴板了，多半是当前选的不是豆包，或 iframe 还没建好
3. 切到豆包那一帧的控制台（DevTools 的 Console 左上角 `top` 下拉）看有没有 `[AI 自动填写] 收到题目`。**iframe 里的日志不会显示在顶层控制台**，这一步最容易漏

**Q：填进去了但没发出去？**
控制台会打一张周边按钮的表。在豆包页面敲 `fbaiDump()` 也能随时看。贴到 issue 里，`距右下角` 那一列最小的就是真的发送按钮。

**Q：公式题显示不正常？**
解析正文是把接口返回的 HTML 直接 `innerHTML` 注入的（和粉笔自己渲染的是同一份）。粉笔的原生 `app-format-html` 组件可能对公式（MathLive）做了额外处理，注入的原始 HTML 有可能渲染不到位。遇到的话开 issue 附上题目。

**Q：正确选项的高亮还是慢？**
选项高亮由粉笔原生逻辑负责，脚本没有接管。接口返回里有 `correctAnswer.choice`，理论上可以自己上色，但改动选项组件风险较高，所以没做。

## 已知限制

- 只在**背题页**（`/ti/memorize/...`）实测过。做题页、模考页的 DOM 结构不同，不保证生效。
- **自定义刷题靠改请求实现**：在 `updateUserQuestionInfo` 的 query 里换掉 `questionCount`。字段名是探针量出来的，但**粉笔哪天把它挪进 body 或者改名，这个功能就会静默失效** —— 输入框还在、数字也填得进去，就是不出效果。验证办法是敲个数、点保存，看右下角有没有弹出那条「出题数量已改为 N」的提示（见[上面那一节](#自定义刷题任意出题数量)）。
- 依赖粉笔的接口路径和 `data-question-key` 属性；`ai-autofill` 依赖豆包的 DOM 形状。任一方改版都可能失效，上面几条自检日志和 `fbaiDump()` 就是用来快速定位的。
- **手柄脚本的两个环境依赖**：震动要 `vibrationActuator`，**只有 Chrome / Edge 有**（Firefox、Safari 上答完题不震，其余功能照常）；键位按「标准映射」的索引认，手柄报的不是标准映射时默认键位可能全错，得自己重绑（设置面板会提示）。
- **手柄脚本不猜当前题号就不会错得离谱，但仍有一个窗口**：用鼠标滚轮滚走之后如果布局脚本没能及时更新 `data-fbai-current-question`，手柄可能还认着旧题号。所以**建议跟布局脚本一起装**。这是目前最需要盯的一处 —— 猜错的代价是永久锁掉一道没做过的题。
- 题目内容全部来自粉笔自己的接口，脚本不生成也不存储任何题目内容。
- 自动发送打开后，**白名单内的页面可以替你按下发送**。挡住这件事的只有 `allowedOrigins`，所以那份清单里不能出现通配符，也不要往里加你不信任的域名。

## 更新日志

### 手柄 0.1

- 新增 `fenbi-gamepad.user.js`。手柄刷题：选选项、提交、翻题、滚动、展开解析、询问 AI、跳题、交卷、回退、开关 AI 面板
- 键位全部可自己映射，不用改代码 —— 换手柄不用改脚本
- **绑定模型：一条绑定 = 一个键 + 一种按法**（短按 / 长按），挂在被触发的那个动作身上。设置面板里录键之前先选短按还是长按，一组内两件短按（或两件长按）互相顶掉，同一组的一短一长可以并存。这是从旧模型改过来的 —— 旧模型把长按单存一张表，说「按住 toggleAi 的键触发交卷」，于是交卷自己没有键、面板上显示成「只在长按里」。旧存储会在启动时自动折算成新格式，老长按接着能用
- 答对震两下短的、答错震一下长的（≤ 0.5 秒）
- 布局脚本新增 `data-fbai-current-question` 属性
- **交卷的确认框能用十字键选**：↑↓ 在「取消 / 确认」之间挪，面键 1 按下去。弹窗开着时是模态的，别的动作一律不理（不然就是隔着一层弹窗把底下的题答了），Back 是「取消」不是退回上一页。光标默认停在「取消」上
- **每个动作都统一成「点一个 DOM 元素」**。原来开关 AI 面板走的是 `fbai-toggle` 事件信道 —— 全部动作里唯一一个不是点 DOM 的，坏了得同时怀疑两份脚本。现在手柄直接点侧边栏上的按钮：展开时点头部的收起键，收起后点边上常显的小标（这个小标是新增的，用户要「关掉了还得能一眼看回来」）。状态由宿主元素上的 `data-fbai-hidden` 说
- **交卷和回退网页各有自己的键了**（摇杆下压 L3 / R3），面板上不再显示「只在长按里，没有独立按键」
- **修「交卷用不了」**：粉笔的交卷按钮是 `<div class="submit-btn">`，不是 `button`/`a` —— 原来只扫后两种，所以永远找不到它，表现是长按 Start 毫无反应、日志里也不留痕迹。改成先认 class，认不得再按整块文字找
- **修「AI 窗口关不掉」**：独立窗口模式下 AI 在一个真窗口里，收起面板原来只把页面上那块藏起来，用户盯着的那扇窗纹丝不动。现在收起时会把自己开的那扇窗关掉（只关自己开的）
- 修「展开/收起解析按了没反应」：原先是按**以「展开」开头**去找按钮，而那个按钮上的字早期是「解析和展开 ▾」，「展开」在第 4 个字，一条都匹配不上。改成先认 class，认不得再按**包含**匹配
- 修设置面板显示「未连接」：原先是取 `getGamepads()[0]`，而那个数组是**按手柄索引**排的 —— 手柄在索引 1 上时读到的就是 `null`，角标亮着面板却说没连接。改成扫描全部槽位
- 修设置面板把交卷、回退网页标成「未绑定」（它们是长按分支，本来就没有独立按键）—— 后来改成绑定模型，这条整个不存在了
- 修「重新绑定」是**追加**语义：换个键会变成两个键都触发。改成替换；后来又收窄成「只替换同一档」—— 给交卷换短按不该把它那条长按也带走

### 布局 2.14 / 侧边栏 2.4

- **三栏改成按比例切**。屏幕横向切 **AI 面板 | 答题区 | 答题卡**，前两栏是屏幕宽度的百分比（22% / 15%），答题区吃剩下的。以前是三个写死的 px 数（380 / 256 / 上限 900），同一个值在 1920 上占两成、在 1280 上占三成，「占多宽」跟着屏幕悄悄变
- **答题区不再有 900px 上限**，随屏幕缩放。撤掉它得同时显式写 `max-width: none` —— 粉笔自己给 `.memorize-main` 写了 `max-width: var(--screen-width)`，原来是我们那条 `!important` 压着它
- **答器区改成真的让位**：以前 AI 面板浮在题目左边、两者可以重叠，现在答题区的左右 margin 就是那两栏的宽度。**1600px 以下答题区比以前窄，以上比以前宽**（1920 上 1140 原来 900；1440 上 838 原来 900）
- 几何只算一处：让位量引用的是栏宽那两个表达式本身（`AI_COLUMN` / `CARD_COLUMN`），下限一触发两边一起动。答题区 `width: auto` + 两条 margin，不再写 `calc(100% - ...)`
- 两栏各有**下限**（AI 260px、卡 180px）：900px 的屏上答题卡按 15% 只有 135px，减掉四周留白剩 87px，题号会挤成一列 —— 名义上按占比了，实际上不能用
